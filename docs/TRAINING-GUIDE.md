# คู่มือเทรน LoRA — PixelSmith Image Studio

คู่มือนี้อธิบายทุกฟังก์ชันของระบบเทรน LoRA ในตัวแอป: ทำอะไร, ปรับแล้วเกิดอะไร, ข้อดี/ข้อเสีย, และค่าที่แนะนำ
ใช้ได้ทั้ง **SANA 1.5** และ **SDXL** (ค่าบางอย่างใช้กับตระกูลเดียว)

> **มีในแอปด้วย:** เปิดแท็บ **เทรน LoRA** → ปุ่ม **📘 คู่มือการเทรน**
> เนื้อหาเดียวกับไฟล์นี้ แต่มีสารบัญ ค้นหา และสลับภาษาไทย/อังกฤษได้ทันที

> สรุปสั้น: คุณภาพของ LoRA มาจาก **dataset + caption** มากกว่าการจูน optimizer
> ถ้ามีเวลาให้แก้อย่างเดียว ให้แก้รูปและ caption ก่อน

---

## 1. ภาพรวมขั้นตอนการเทรน

1. **เลือกโมเดลฐาน** — SANA หรือ SDXL (ต้องเป็นตระกูลเดียวกับ LoRA ที่อยากได้)
2. **สร้าง dataset** — ตั้งชื่อ, trigger, ประเภทคอนเซปต์
3. **อัปโหลดรูป** — ใส่ tag/trigger/repeats ต่อรูป
4. **เขียน caption** — บอกสิ่งที่เปลี่ยนในภาพ (ฉาก/ท่า/ชุด) ไม่บอกสิ่งที่เหมือนกันทุกภาพ
5. **ตรวจ QC** — ดูขนาด/สัดส่วน/ไฟล์ซ้ำ/แคปชันที่ขาด
6. **เลือก preset หรือตั้งค่าเอง** — เริ่มจาก preset แล้วปรับเฉพาะที่จำเป็น
7. **เริ่มเทรน** — เข้าคิว ปล่อยโมเดล generate ก่อนอัตโนมัติ
8. **สร้างภาพทดสอบ** — เทียบ checkpoint/ค่า setting ด้วย seed คงที่
9. **เลือก checkpoint ที่ดีที่สุด** — ไม่จำเป็นต้องใช้ step สุดท้ายเสมอ

---

## 2. ประเภทคอนเซปต์ (Dataset kind)

ประเภทไม่ได้เปลี่ยนอัลกอริทึมเทรน แต่เปลี่ยน **เช็กลิสต์รูป, คำแนะนำ caption, ค่า preset, และนโยบายรูปหลายตัวละคร**

| ประเภท | ใช้เมื่อ | จำนวนรูปแนะนำ | caption ควรเน้น |
|---|---|---|---|
| **Character** (ตัวละคร) | อยากให้โมเดลจำใบหน้า/ตัวตน | 16–30 รูปเดี่ยว หลายมุม | ฉาก/ท่า/ชุด/แสง — **ไม่บรรยายลักษณะถาวร** (ผมสี, ตาสี, หุ่น) |
| **Style** (สไตล์ภาพ) | อยากได้สไตล์สี/เส้น/แสง | 20–30+ รูป หลากหลายเนื้อหา | บรรยายเนื้อหาให้ละเอียด — **ไม่บรรยายสไตล์** (ปล่อยให้ trigger ดูดสไตล์) |
| **Outfit / object** (ชุด/ของ) | อยากให้จำชุด/ไอเทม | 10–20 รูป เห็นชิ้นงานชัด | รายละเอียดชิ้นงานที่คงที่ (สี, โลโก้, วัสดุ) |
| **Pose / concept** (ท่า/คอนเซปต์) | อยากให้จำท่าหรือมุม | 20–40 รูป หลายมุมกล้อง | ชื่อท่า/คอนเซปต์ + มุมกล้อง |

**ข้อควรรู้**
- ประเภท `style`/`outfit`/`pose` จะ **บังคับใช้รูปหลายตัวละครแบบ include** (ใช้น้ำหนักเท่ากัน) เพราะเนื้อหาหลักไม่ใช่ตัวละครเดียว
- ประเภท `character` ค่าเริ่มต้นคือ **exclude** รูปหลายตัวละคร เพื่อไม่ให้ trigger ไปจำตัวละครประกอบ
- เปลี่ยนประเภทได้ตลอด แต่ควรเปลี่ยนก่อนเริ่มเทรนรอบจริง

## 3. Trigger word และ Extra triggers

**Trigger** คือคำพิเศษที่ผูกทุกภาพเข้าด้วยกัน (เช่น `lola`, `mytrigger7`)
ตอน generate ใส่คำนี้ในพรอมป์ตเพื่อเรียกคอนเซปต์

- **Trigger หลัก** — 1 คำ ควรไม่ซ้ำกับคำทั่วไปในภาษาอังกฤษ
- **Extra triggers** (สูงสุด 5) — คำเรียกสำรอง/ชื่อชุด/ชื่อท่า เช่น `armor form`, `casual outfit`
- **Trigger ต่อรูป** — ใช้เมื่อบางรูปต้องใช้คำอื่น (เช่น รูปชุดเกราะใช้ `armor form`)

ระบบจะ **เติม trigger ให้อัตโนมัติ** ถ้า caption ไม่มี — เพื่อไม่ให้ trigger หายไปจากคู่ภาพ
ถ้า caption มีคำนั้นอยู่แล้ว ระบบจะไม่เติมซ้ำ

**ข้อดี:** ควบคุมการเรียกคอนเซปต์ได้แม่น, แยกหลายรูปแบบได้
**ข้อเสีย:** trigger ที่ซ้ำคำธรรมดา (เช่น `girl`, `red`) จะทำให้ปนกับของเดิม
**แนะนำ:** ใช้คำแปลก ๆ ตัวพิมพ์เล็ก เช่น `lola7`, `foxstyle2`

## 4. Caption, Tags และ Repeats ต่อรูป

### Caption
ข้อความบรรยายภาพ ระบบจะประกอบเป็น:
`trigger, tag1, tag2, … , caption อิสระ`

- **ควรเขียน:** สิ่งที่แตกต่างในแต่ละรูป (ฉาก, ท่า, มุมกล้อง, ชุด, แสง, อารมณ์)
- **ไม่ควรเขียน:** ลักษณะถาวรของคอนเซปต์ (ใบหน้า, สีผม, หุ่น) เพราะจะทำให้ trigger เรียนไม่เต็มที่
- ภาษาอังกฤษให้ผลดีที่สุด (โมเดลเข้าใจตรงกว่า)

### Tags
ป้ายสั้น ๆ ที่แทรกได้เร็วจากแถบ tag (front view, close-up, sitting ฯลฯ)
- สูงสุด 20 tag ต่อรูป
- ใช้เพื่อสอนให้แยก "มุม/ท่า" ออกจาก "ตัวตน"
- ถ้า tag ซ้ำกับ caption ระบบจะไม่เพิ่มซ้ำ

### Repeats (1–10)
จำนวนรอบที่รูปนั้นถูกใช้ต่อ epoch
- รูปที่สำคัญ/มีน้อย → เพิ่ม repeats 2–3
- รูปที่ซ้ำ/คุณภาพต่ำ → ลดเหลือ 1 หรือลบออก
- **ข้อควรระวัง:** repeats สูงเกินไปจะทำให้ overfit รูปนั้น

### Multi flag (รูปหลายตัวละคร)
ใช้กับประเภท `character` — ทำเครื่องหมายว่ารูปมีตัวละครอื่นด้วย
- `exclude` (ค่าเริ่มต้น): ข้ามรูปเหล่านี้
- `weighted`: ใช้แต่ลดน้ำหนัก (ค่าเริ่มต้น 25%)
- `include`: ใช้เต็มน้ำหนัก

**แนะนำ:** ถ้าเป็น character LoRA ให้ใช้ `exclude` เป็นหลัก แล้วเก็บรูป multi ไว้อีก dataset
ถ้าอยากให้ LoRA รู้จักการอยู่ร่วมกับตัวละครอื่น ให้ใช้ `weighted` และใส่ caption `with another character`

## 5. Aspect-ratio bucketing

**ทำอะไร:** เลือกขนาดกล่อง (bucket) ที่ใกล้สัดส่วนรูปจริงที่สุด แล้ว resize/ครอปให้น้อยที่สุด
แทนที่จะบังคับทุกภาพเป็นจัตุรัส (ซึ่งครอปภาพแนวตั้ง/แนวนอนทิ้งเยอะ)

ตัวอย่าง bucket ที่ resolution 1024: 1024×1024, 1152×896, 896×1152, 1216×832, 832×1216, 1344×768, 768×1344

- **ข้อดี:** เก็บองค์ประกอบภาพได้ครบ, ฝึกภาพแนวตั้ง/แนวนอนได้ตรงสัดส่วน, คุณภาพดีขึ้นชัดกับ dataset ที่มีภาพหลายสัดส่วน
- **ข้อเสีย:** ใช้หน่วยความจำมากกว่าเล็กน้อย, โมเดลเห็นขนาดหลากหลายขึ้น (ปกติไม่เป็นปัญหา)
- **แนะนำ:** **เปิด** (ค่าเริ่มต้น) ทุกกรณี
- **ปิดเมื่อ:** ต้องการเปรียบเทียบกับพฤติกรรมเดิม หรือ dataset เป็นจัตุรัสทั้งหมด

> SANA รองรับ latent ขนาดต่างกันได้ตามธรรมชาติ (dynamic RoPE)
> SDXL ต้องส่ง `time_ids` ต่อรูป ระบบจัดการให้อัตโนมัติ

## 6. Caption dropout

**ทำอะไร:** สุ่มทิ้ง caption ทั้งหมดของ step นั้น (ใช้ embedding ว่างแทน) ตามความน่าจะเป็นที่ตั้ง
- **ข้อดี:** ฝึก unconditional/negative ให้แข็งขึ้น, ลดการพึ่ง caption มากเกินไป, ช่วยเรื่อง composition
- **ข้อเสีย:** มากเกินไปจะทำให้ความสัมพันธ์ trigger↔ภาพอ่อนลง (LoRA ตอบ trigger ไม่แม่น)
- **ช่วงค่า:** 0–0.3
- **แนะนำ:** `0.05` (ค่าเริ่มต้น) สำหรับ character/outfit · `0.02–0.05` สำหรับ style · `0` ถ้า trigger ต้องแม่นมาก
- **ห้ามเกิน:** 0.15 สำหรับ dataset เล็ก (น้อยกว่า 20 รูป)

## 7. Caption shuffle + Keep tokens

**ทำอะไร:** สร้าง caption หลายลำดับคำ (สลับเฉพาะส่วนหลัง) แล้วสุ่มใช้แต่ละ step
- **ข้อดี:** กันโมเดลยึดลำดับคำ, ทำให้แต่ละแท็กถูกเรียนรู้แยกกัน, ช่วย generalize
- **ข้อเสีย:** ถ้า caption สั้นมาก การสลับแทบไม่มีผล; ถ้า keep_tokens=0 อาจสลับ trigger ไปอยู่กลางประโยค (ปกติยังเรียนได้)
- **Keep tokens (0–4):** จำนวนส่วนแรก (คั่นด้วย comma) ที่ **ไม่ถูกสลับ** — กัน trigger/คำสำคัญหลุดตำแหน่ง
- **แนะนำ:** เปิดเฉพาะ **style** และ caption ที่มีหลายแท็ก · keep_tokens = `1` (กัน trigger) หรือ `2` (trigger + คำสำคัญ)
- **character:** ปิดไว้ก่อน เพื่อให้ความสัมพันธ์กับ trigger ตรงที่สุด

---

## 8. Noise offset

**ทำอะไร:** บวกค่า offset แบบสุ่มแยกตาม channel ลงใน noise ตอนเทรน
- **ข้อดี:** ช่วย dataset ที่มืดมาก/สว่างจัด/คอนทราสต์สูง ให้โมเดลสร้างแสงเงาสมดุลขึ้น
- **ข้อเสีย:** สูงเกินไปทำให้ภาพออกเทา/contrast เพี้ยน
- **ช่วงค่า:** 0–0.2
- **แนะนำ:** `0` สำหรับงานทั่วไป · `0.02–0.05` สำหรับ dataset ที่มืด/กลางคืน/backlight · `0.1` เฉพาะกรณีสุดโต่ง
- **หมายเหตุ:** ไม่เกี่ยวกับการแก้ภาพที่ generate แล้ว — เป็นการปรับการเรียนเท่านั้น

---

## 9. Min-SNR gamma

**ทำอะไร:** ถ่วงน้ำหนัก loss ตาม SNR ของ timestep: `weight = clamp(SNR, max=gamma) / SNR`
- **ข้อดี:** ลดอิทธิพลของ step ที่ noisy มาก/น้อยเกินไป, เรียนโครงสร้างเร็วขึ้น, เสถียรกับ LR สูง
- **ข้อเสีย:** อาจทำให้รายละเอียดเล็ก ๆ (ผิว/ลายผ้า) น้อยลงถ้า gamma สูงเกินไป
- **ช่วงค่า:** 0 (ปิด) – 20
- **แนะนำ:** `0` (ปิด) สำหรับ **character** เพราะต้องการความเหมือนใบหน้า/ตัวตน
  · `5` สำหรับ **style** · `5–10` เมื่อเทรนด้วย LR สูงหรือ step น้อย
- **SANA:** ใช้สูตร flow-matching `SNR = ((1-σ)/σ)²`
- **SDXL:** ใช้ `SNR = α/(1-α)` จาก DDPM schedule

## 10. rsLoRA

**ทำอะไร:** เปลี่ยน scaling ของ LoRA จาก `alpha/r` เป็น `alpha/√r`
- **ข้อดี:** rank สูง (64–128) เรียนได้เสถียรขึ้น, gradient ไม่ระเบิด/หายง่าย
- **ข้อเสีย:** ไฟล์ที่ได้ต้องแปลง scaling กลับเป็นแบบมาตรฐานตอนบันทึก (ระบบทำให้อัตโนมัติ) — โปรแกรมอื่นที่อ่าน metadata อาจต้องตั้ง alpha เอง
- **แนะนำ:** เปิดเมื่อใช้ **rank 64 ขึ้นไป** · ปิดสำหรับ rank 4–32 (ค่าเริ่มต้น)
- **ความเข้ากันได้:** ไฟล์ที่บันทึกจะใช้ standard scaling เสมอ (`lora_B` ถูกคูณ `√r` ก่อนเซฟ) จึงโหลดกับ diffusers ปกติได้

## 11. Target modules (ขอบเขตการเรียน)

| ค่า | เรียนอะไร | ข้อดี | ข้อเสีย |
|---|---|---|---|
| **attn** (ค่าเริ่มต้น) | q, k, v, out ของ attention | เบา เร็ว ไฟล์เล็ก ปลอดภัย | รายละเอียด texture/โครงสร้างอาจไม่ลึก |
| **attn_ff** | attention + feed-forward | จำรายละเอียด/โครงสร้างเก่งขึ้น | ช้ากว่า ~30–50%, ไฟล์ใหญ่ขึ้น, overfit ง่ายขึ้น |

- SANA FF: `ff.conv_inverted`, `ff.conv_point`
- SDXL FF: `ff.net.0.proj`, `ff.net.2`
- **แนะนำ:** `attn` สำหรับ character/outfit · `attn_ff` เมื่อรู้สึกว่า LoRA "จำรายละเอียดไม่พอ" และมี step เหลือ

## 12. Rank (ขนาด LoRA)

**ทำอะไร:** จำนวนมิติของเมทริกซ์ LoRA — ยิ่งสูงยิ่งจุรายละเอียดได้มาก
- **ข้อดี rank สูง:** จำรายละเอียด/หลายรูปแบบได้ดี
- **ข้อเสีย rank สูง:** ไฟล์ใหญ่, overfit ง่าย, ต้องใช้ step มากขึ้น, ช้ากว่าเล็กน้อย
- **แนะนำ:**
  - character: **32** (16–64)
  - style: **32** (16–64)
  - outfit/object: **16** (8–32)
  - pose/concept: **16–32**
  - ทดลองเร็ว ๆ: **16**
- ถ้าเทรนต่อจาก LoRA เดิม ระบบจะใช้ rank ของไฟล์เดิมอัตโนมัติ (เพื่อโหลดน้ำหนักได้)

---

## 13. Steps และ Epochs

**Steps** = จำนวนรอบอัปเดต optimizer ทั้งหมด
**Epochs** = จำนวนรอบที่วนครบ dataset (ใช้กับเครื่องคิดเลข)

สูตรเครื่องคิดเลข:
```
steps ≈ (ผลรวม repeats ของทุกรูป × epochs) / grad_accum
```

- **ข้อดี steps มาก:** เรียนครบ, รายละเอียดดี
- **ข้อเสีย steps มากเกิน:** overfit (สีเพี้ยน, จำภาพต้นฉบับ, ตอบพรอมป์ตอื่นไม่ได้)
- **แนะนำ:**
  - character: **1,000–1,500** (dataset 16–30 รูป)
  - style: **1,500–2,500**
  - outfit: **800–1,200**
  - pose: **1,200–2,000**
  - SANA ทางการใช้ 500 steps rank 4 — แต่น้อยเกินไปสำหรับ likeness; ค่าข้างบนคือช่วงใช้งานจริง
- **สำคัญ:** บันทึก checkpoint ทุก 100–250 step แล้วเลือก step ที่ดีที่สุด

---

## 14. Learning rate (LR)

**ทำอะไร:** ขนาดก้าวในการปรับน้ำหนัก
- **สูงเกิน:** loss แกว่ง, ภาพเพี้ยน, overfit เร็ว
- **ต่ำเกิน:** เรียนช้า, ต้องเพิ่ม step, อาจเรียนไม่ทัน
- **แนะนำ:**
  - SANA: **1e-4 – 2e-4** (ค่าเริ่มต้น 2e-4)
  - SDXL: **1e-4** (ช่วง 5e-5 – 2e-4)
  - rank สูง/attn_ff: ใช้ช่วงล่าง
- ระบบจำกัด 1e-5 – 5e-4

## 15. LR schedule + Warmup

| ค่า | พฤติกรรม | เหมาะกับ |
|---|---|---|
| **Cosine + warmup** | ค่อย ๆ ขึ้นแล้วลดลงแบบ cosine | งานจริงเกือบทั้งหมด |
| **Constant** | LR คงที่ตลอด | run สั้น, ทดลอง, SANA official |

**Warmup ratio** (0–0.2, ค่าเริ่มต้น 0.03) = สัดส่วน step แรกที่ค่อย ๆ เพิ่ม LR
- ช่วยกัน loss ระเบิดช่วงเริ่ม
- dataset เล็ก/LR สูง → เพิ่มเป็น 0.05–0.1

---

## 16. Timestep sampling

| ค่า | ทำอะไร | เหมาะกับ |
|---|---|---|
| **Logit-normal** (ค่าเริ่มต้น) | สุ่ม timestep เน้นช่วงกลาง | งานจริง, เรียนโครงสร้าง+รายละเอียดสมดุล |
| **Shift / Uniform** | สุ่มกระจายเท่ากัน | ทดลอง, เทรนสั้น, อ้างอิงสูตรเดิม |

- Logit-normal ให้ผลดีกว่าในจำนวน step ที่น้อย
- ถ้าผลออกมา "แข็ง/แบน" ลองสลับเป็น uniform เพื่อดูความต่าง

---

## 17. EMA weights

**ทำอะไร:** เก็บค่าเฉลี่ยของน้ำหนัก LoRA ตลอดการเทรน แล้วบันทึกค่าเฉลี่ยเป็นผลลัพธ์
- **ข้อดี:** ผลเนียนขึ้น ลด noise ระหว่าง step
- **ข้อเสีย:** ทำให้ LoRA "อ่อนลง" (‖BA‖ ต่ำ), run สั้นจะได้ผลอ่อนเกิน
- **แนะนำ:** เปิดเฉพาะ run ยาว (≥2,000 step) · ปิดสำหรับ run สั้น/character ที่ต้องการ likeness แรง
- **EMA decay** (0.9–0.9999, ค่าเริ่มต้น 0.999): ยิ่งสูงยิ่งเฉลี่ยนานขึ้น

---

## 18. Grad accumulation

**ทำอะไร:** สะสม gradient หลาย micro-step ก่อนอัปเดต 1 ครั้ง
- **ข้อดี:** เทรนได้ effective batch ใหญ่ขึ้นโดยใช้ VRAM เท่าเดิม, gradient เสถียรขึ้น
- **ข้อเสีย:** ช้าลงตามจำนวนเท่า (1 step ใช้เวลานานขึ้น)
- **แนะนำ:** `1` (ปกติ) · `2` เมื่อ dataset เล็กมากหรือ loss แกว่ง · ไม่เกิน 4 บนการ์ด 10 GB

---

## 19. Resolution

**ทำอะไร:** ขนาดเป้าหมายของ bucket (ไม่ได้บังคับภาพเป็นจัตุรัสเมื่อเปิด bucketing)
- SANA: 512 / 768 / 1024
- SDXL: 512 / 768 / 1024 (แนะนำ 768 บนการ์ด 10 GB)

- **สูง:** รายละเอียดดี แต่ใช้ VRAM/เวลามาก
- **ต่ำ:** เร็ว แต่ใบหน้า/ผิวอาจไม่คม
- **แนะนำ:** SANA 1024 · SDXL 768 (หรือ 1024 ถ้า VRAM พอและลด batch/attn_ff)

---

## 20. Seed

- `-1` = สุ่มใหม่ทุกครั้ง
- ใส่ค่าคงที่เมื่อต้องการ **เทียบผลระหว่างการทดลอง** (เช่น เปลี่ยน LR/step แล้วดูความต่าง)
- seed มีผลกับลำดับการสุ่มรูป, timestep, noise — ไม่ใช่คุณภาพโดยตรง

---

## 21. Prompt enhance ตอนเทรน

**ทำอะไร:** ใช้ตัวขยายพรอมป์ตตัวเดียวกับตอน generate ก่อน encode caption
- **ข้อดี:** caption ยาว/ละเอียดขึ้น อาจช่วยเรื่อง composition
- **ข้อเสีย:** ทำให้ caption ไม่ตรงกับที่เขียน 100%, เพิ่มเวลาช่วงเตรียม, และทำให้ debug ยาก
- **แนะนำ:** เปิด (ค่าเริ่มต้น) ถ้า caption สั้น · ปิดเมื่อต้องการควบคุมคำทุกคำหรือกำลังไล่ปัญหา caption

---

## 22. Augmentation: สุ่มพลิกภาพซ้าย-ขวา

- **ข้อดี:** เพิ่มความหลากหลาย, กัน overfit รูปน้อย
- **ข้อเสีย:** อันตรายกับตัวละครที่มีลักษณะไม่สมมาตร (ไฝ, ผมแสกข้าง, เครื่องหมาย) และข้อความในภาพ
- **แนะนำ:** เปิดเฉพาะ **style** · ปิดสำหรับ character/outfit ที่มีรายละเอียดข้างชัดเจน

---

## 23. Checkpoints และ Resume state

### Checkpoint ทุก N steps (`save_every`)
- บันทึก LoRA ระหว่างเทรนเป็นไฟล์ `ชื่อ-stepN.safetensors`
- `0` = บันทึกเฉพาะไฟล์สุดท้าย
- **แนะนำ:** 100–250 สำหรับ run สั้น, 250–500 สำหรับ run ยาว
- ระบบจะไม่เขียนทับไฟล์ที่มีอยู่แล้ว

### Resume จาก optimizer state
- ระบบเก็บไฟล์ `.trainstate.pt` คู่กับ checkpoint (optimizer, scheduler, RNG, EMA, step, loss)
- เปิด `Resume จาก optimizer state` + เลือก LoRA ตั้งต้น (checkpoint) ที่มี `.trainstate.pt` → เทรนต่อจาก step เดิม
- **ข้อดี:** ไม่ต้องเริ่มนับ step ใหม่, LR schedule/optimizer ต่อเนื่อง
- **ข้อเสีย:** ต้องมีไฟล์ state และ rank ตรงกัน; ถ้าไม่มีจะเริ่มจาก 0
- **แนะนำ:** เปิดเมื่อเทรนต่อจาก checkpoint เดิม · ปิดเมื่อเริ่ม LoRA ใหม่

> การเทรนต่อจาก LoRA เดิม (`Continue from LoRA`) แต่ไม่เปิด resume state จะเริ่ม step ใหม่แต่โหลดน้ำหนักเดิม — เหมาะกับการ refine

---

## 24. Continue from LoRA (init_lora)

**ทำอะไร:** โหลดน้ำหนัก LoRA เดิมเป็นจุดเริ่มต้นก่อนเทรน
- **ข้อดี:** ต่อยอดสไตล์/ตัวตนเดิม, ใช้ step น้อยลง
- **ข้อเสีย:** ถ้า LoRA เดิม overfit อยู่แล้ว จะยิ่ง overfit; rank ถูกบังคับตามไฟล์เดิม
- **แนะนำ:** ใช้เมื่ออยากปรับ LoRA ที่มีอยู่ (เพิ่มชุด/แก้สี) · ตั้งชื่อผลลัพธ์ใหม่เสมอ

---

## 25. นโยบายรูปหลายตัวละคร (Multi-character)

| โหมด | ใช้รูป | น้ำหนัก | เหมาะกับ |
|---|---|---|---|
| **Exclude** | เฉพาะรูปเดี่ยว | 1.0 | character LoRA (ค่าเริ่มต้น) |
| **Weighted** | ทุกรูป | รูป multi = 5–100% | character ที่อยากให้อยู่ร่วมฉากได้ |
| **Include** | ทุกรูป | 1.0 | style/outfit/pose (บังคับอัตโนมัติ) |

- **Weighted weight** แนะนำ 20–30% (ค่าเริ่มต้น 25%)
- ถ้าเลือก weighted/include ควรใส่ caption `with another character` ให้รูป multi

---

## 26. Thermal guard (ป้องกัน GPU ร้อน)

ระบบตรวจอุณหภูมิทุก N step และเลือกได้ 2 โหมด:

| โหมด | ทำอะไร | ข้อดี | ข้อเสีย |
|---|---|---|---|
| **Throttle** (แนะนำ) | ลด clock ลงทีละระดับ (ค่าเริ่มต้น 5%, สูงสุด 25%) | เทรนไม่หยุด, อุณหภูมินิ่ง | ช้าลงเล็กน้อย |
| **Pause** | หยุดพักจนเย็นถึง threshold | เย็นกว่า | step ใช้เวลานานขึ้นมาก |

- **เริ่มชะลอเมื่อ** 87°C · **กลับมาเต็ม speed** 80°C · **หยุดฉุกเฉิน** 90°C (ปรับได้ในกรอบปลอดภัย)
- ถ้าไม่มีสิทธิ์ sudo ระบบจะหน่วงระหว่าง step แทนการปรับ clock
- **แนะนำ:** เปิด throttle ไว้เสมอ · อย่าตั้ง max เกิน 90°C

---

## 27. Dataset QC

ปุ่ม **ตรวจคุณภาพ dataset (QC)** รายงาน:
- จำนวนรูปทั้งหมด / เดี่ยว / หลายตัวละคร
- ขนาด (กว้าง×สูง) และ bucket ที่จะใช้
- ไฟล์ซ้ำ (SHA-1 ตรงกัน)
- รูปที่ไม่มี caption/tags
- รูปเล็กกว่า 512px
- สัดส่วนสุดโต่ง (aspect < 0.4 หรือ > 2.5)
- คำแนะนำสรุป

**วิธีใช้:** กด QC → แก้ปัญหาที่ขึ้นคำเตือน → กด QC ซ้ำ → เริ่มเทรน
QC ไม่ลบหรือแก้อะไรให้อัตโนมัติ (ปลอดภัยกับข้อมูล)

**เกณฑ์ที่ควรผ่าน:**
- ไม่มีไฟล์ซ้ำ
- รูปเดี่ยว ≥ 16 (character)
- ทุกรูปมี caption หรือ tags
- ด้านสั้น ≥ 512px

## 28. สร้างภาพทดสอบหลังเทรน (Sample generation)

**ทำอะไร:** ส่งงาน generate ปกติโดยใช้ LoRA ที่เลือก (batch 4, seed คงที่ 12345, พรอมป์ต = trigger ของ dataset ถ้าเว้นว่าง)
- **ข้อดี:** เห็นผลจริงทันทีโดยไม่ต้องโหลดโมเดลซ้ำ, เทียบ checkpoint ได้ด้วย seed เดียวกัน
- **ข้อเสีย:** ใช้เวลาคิวปกติ (ไม่ใช่ instant)
- **วิธีใช้:** เลือก LoRA → ใส่พรอมป์ต (หรือเว้นว่าง) → กดสร้างภาพทดสอบ
- **แนะนำ:** สร้าง 2–3 checkpoint แล้วเทียบภาพที่ seed เดียวกัน

## 30. ความแตกต่าง SANA vs SDXL

| หัวข้อ | SANA 1.5 | SDXL |
|---|---|---|
| VRAM ตอนเทรน | ต่ำกว่า | สูงกว่า |
| ความเร็ว | เร็วกว่า | ช้ากว่า |
| Rank แนะนำ | 32 | 16–32 |
| Resolution แนะนำ | 1024 | 768 (หรือ 1024 ถ้าไหว) |
| LR แนะนำ | 1e-4 – 2e-4 | 1e-4 |
| Steps แนะนำ | 1,000–2,500 | 1,000–2,000 |
| Bucketing | dynamic RoPE รองรับเอง | ต้องใช้ time_ids ต่อรูป (ระบบทำให้) |
| attn_ff | conv modules | linear FF modules |
| ข้อจำกัด | เทรนได้เฉพาะ transformer | เทรนได้เฉพาะ UNet |

> **ห้ามโหลดสอง pipeline พร้อมกัน** บนการ์ด 10 GB — ระบบปล่อยโมเดล generate ก่อนเทรนให้อัตโนมัติ

## 32. ปัญหาที่พบบ่อย

| อาการ | สาเหตุ | แก้ |
|---|---|---|
| ภาพออกมาไม่เหมือนตัวละคร | รูปน้อย/มุมซ้ำ/caption บรรยายลักษณะถาวร | เพิ่มรูปหลายมุม, ย้ายลักษณะถาวรออกจาก caption, เพิ่ม steps |
| LoRA ตอบ trigger ไม่แม่น | caption dropout สูง, steps น้อย, trigger ซ้ำคำธรรมดา | ลด dropout, เพิ่ม steps, เปลี่ยน trigger |
| ภาพแข็ง/สีเพี้ยน/จำต้นฉบับ | overfit | ลด steps/LR, ใช้ checkpoint ก่อนหน้า, เพิ่ม dropout เล็กน้อย |
| รายละเอียดใบหน้าไม่คม | resolution ต่ำ, rank ต่ำ | เพิ่ม resolution/rank, เปิด attn_ff |
| ภาพแนวตั้งถูกครอป | bucketing ปิด | เปิด bucketing |
| ภาพมืด/contrast เพี้ยน | noise offset สูงเกิน | ลดเหลือ 0–0.02 |
| loss แกว่ง | LR สูง/dataset เล็ก | ลด LR, เพิ่ม warmup, grad accum 2 |
| เทรนช้ามาก | grad accum/attn_ff/thermal throttle | ลด grad accum, ใช้ attn, ตรวจอุณหภูมิ |
| GPU ร้อน/เครื่องช้า | thermal guard ปิดหรือ max สูง | เปิด throttle, ตั้ง max 88–90°C |
| resume ไม่ต่อ step | ไม่มี `.trainstate.pt` หรือ rank ไม่ตรง | ใช้ checkpoint ที่มี state, ตั้ง rank ให้ตรง |

## 33. เช็กลิสต์ก่อนกดเริ่มเทรน

## 34. หลังเทรน

1. ดูรายการ LoRA → เลือก checkpoint ที่ต้องการ
2. กด **สร้างภาพทดสอบ** ด้วย seed เดียวกัน 2–3 checkpoint

5. เก็บ config ที่ใช้ได้ → export ไว้เป็น recipe
